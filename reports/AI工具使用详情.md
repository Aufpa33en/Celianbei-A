# AI 工具使用详情

本说明依据“策联杯”数学建模竞赛人工智能工具使用规定编写。竞赛期间，参赛队使用人工智能工具辅助资料整理、程序实现与调试、候选方案检查、结果整理和论文文字处理。题目理解、数据处理原则、模型最终选择、实验验收标准、数值核验、结论边界及论文定稿由参赛队主导并负责。

## 1. 所用 AI 工具名称、版本或型号

| 编号 | 工具名称 | 版本或型号 | 主要定位 |
|---|---|---|---|
| AI-1 | OpenAI Codex | OpenAI GPT-5（Codex 桌面端当前会话） | 编程辅助、实验执行、代码审查和资料整理 |
| AI-2 | DeepSeek | DeepSeek V4 Flash（`deepseek-v4-flash`） | 论文文字起草、改写和一致性检查 |
| AI-3 | Claude Code | 2.1.177 | 代码与论文材料的辅助检查 |

本表版本信息依据当前平台会话和项目工具记录填写。未列入本表的普通编辑器、Python、MATLAB、Git及绘图库不作为生成式人工智能工具申报。

## 2. 具体使用目的和环节

| 使用环节 | AI 辅助内容 | 参赛队主导内容 |
|---|---|---|
| 文献与资料整理 | 辅助整理检索关键词、归纳电池寿命预测和快充优化文献中的候选方法 | 判断文献来源是否可靠、方法假设是否适用于本题，并决定引用和建模依据 |
| 原始数据检查 | 辅助编写检查程序、定位异常循环、整理变量和绘图程序 | 确定原始数据只读原则、异常判断标准及“最小干预、保留审计痕迹”的清洗方案 |
| 候选模型讨论 | 辅助归纳候选模型、检查推导中的可辨识性、数据泄漏和外推风险 | 确定各问假设、评价指标、阶段硬门、主模型和结论适用范围 |
| 程序实现与调试 | 辅助实现部分 Python 程序、测试、结果导出和运行时间优化，提示潜在边界问题 | 确定程序输入输出、训练与验证边界、随机种子、验收条件，并复核关键实现 |
| 模型比较与结果整理 | 辅助执行 smoke test、汇总 CSV、比较候选模型并形成审查意见 | 根据交叉验证、bootstrap、置换检验和压力测试结果决定采纳、修改或淘汰模型 |
| 图表与论文写作 | 辅助生成绘图代码、统一术语、整理章节和润色表达 | 对照权威 CSV 和程序输出核对全部数字、限制结论强度并最终定稿 |

AI 未被用作原始数据来源，也未替代参赛队对模型和结论的最终判断。所有正式计算均以仓库中的原始数据、程序和结果文件为准。

## 3. 主要提示方式与使用过程说明

本项目主要采用“人工设定任务与边界—AI 提供实现或审查建议—程序计算与交叉核验—人工决定是否采纳”的使用方式。任务按数据处理、模型推导、smoke test、全量验证和论文整理分阶段进行；在进入下一阶段前，由参赛队检查当前阶段的输出文件、测试结果和结论边界。

以下交互为对实际工作过程的概括性转述，用于说明提示方式，不是逐字聊天记录。

### 3.1 异常循环的处理边界

**人工提出的问题：** 第 12 循环的容量尖峰和零内阻是否可能是题目有意设置的诊断循环，是否应直接“正常化”？

**AI 辅助过程：** 建议先比较同策略重复电池和相邻循环，再检索原始数据集协议，区分真实实验事件与测量异常；同时建议保留原始字段和修复标记，避免覆盖原始数据。

**人工核验与决定：** 参赛队比较了三块重复电池第 11—13 循环，并核对公开数据说明。未发现第 12 循环具有统一诊断用途的证据，最终仅对 3 处异常字段进行局部插值，其他记录不修改；原始值、清洗值和修复标记同时保留。处理依据记录在 `.log/review/2026-08-13_cycle12-purpose-and-modeling-boundary.md`。

### 3.2 问题一候选模型比较

**人工提出的任务：** 在不使用训练集拟合优度和无真实标签的 80% SOH 外推寿命选模的前提下，对多种 SOH 曲线模型进行统一比较。

**AI 辅助过程：** 辅助实现多项式混合、样条混合和函数型岭平滑模型，按整块电池组织交叉验证、配对 bootstrap 和统一结果导出。

**人工核验与决定：** 参赛队预先确定按整块电池留一验证，核查三个模型的误差、策略排序和敏感性。最终选用函数型岭平滑作为主方法，保留样条混合模型作为稳健性对照；由于没有电池真实达到 80% SOH，外推寿命不用于主模型选择。依据见 `.log/change/2026-08-14_q1-python-model-comparison.md` 和 `result/q1/`。

### 3.3 问题二解释模型的降级

**人工提出的问题：** 高 SOC 暴露候选中是否存在可以作为最终解释模型的单一 SOC 阈值，能否据此声称充电参数具有独立显著效应？

**AI 辅助过程：** 辅助比较多个高 SOC 暴露坐标，提示阈值选择、极端策略依赖和参数不可辨识风险，并协助整理 bootstrap 与精确置换结果。

**人工核验与决定：** smoke 阶段曾暂定 `ridge_Jhigh70`，但正式验证显示其选择频率不足，选择校正结果也未达到预设显著性标准；删除极端策略后常数模型胜出。参赛队据此否决单阈值主模型和三参数独立因果解释，只保留“高 SOC 倍率暴露方向一致”的描述性结论。依据见 `.log/review/2026-08-14_q2-formal-model-decision.md` 和 `result/q2/03_formal_validation/`。

### 3.4 问题三预测流程的泄漏检查

**人工提出的任务：** 使用早期循环预测第 151—200 循环 SOH，同时保证特征构造、调参、模型选择和寿命外推不读取被遮蔽的未来数据。

**AI 辅助过程：** 辅助检查相对 SOH 阈值、前缀特征、嵌套预处理、PCA和组合权重，指出初稿中的阈值换算、未来数据拼接和模型筛选偏差风险。

**人工核验与决定：** 参赛队采纳泄漏修正，冻结按整块电池的嵌套留一验证；smoke test只用于排查代码、数值和运行时间问题，不使用9块测试电池答案淘汰模型。全量验证后依据统一指标冻结最终预测模型，并将 80% SOH 寿命限定为情景外推。依据见 `.log/review/2026-08-14_q3-model-hard-gate-review.md`、`reports/q3_full_validation_report.md` 和 `result/q3/`。

### 3.5 问题四连续优化模型的淘汰

**人工提出的任务：** 判断能否在连续的充电参数空间中寻找最优策略，或应将推荐限制在已有观测策略内。

**AI 辅助过程：** 辅助实现连续响应面压力测试、离散 Pareto 分析和整块电池 bootstrap，并整理前沿稳定性与末段斜率敏感性结果。

**人工核验与决定：** 连续代理模型即使在使用真实策略坐标的压力测试中仍未稳定优于常数基线，参赛队据此淘汰连续优化，不报告未观测参数组合的“全局最优”；最终采用观测策略离散 Pareto 和条件推荐，并对审查发现的末段衰减反转、负退化代理和前沿不稳定性逐项修正文稿。依据见 `reports/q4_full_validation_report.md`、`.log/review/2026-08-15_q4-full-results-review-adoption.md` 和 `result/q4/02_full_validation/`。

## 4. 对 AI 输出的采纳、人工修改和核验情况

按照竞赛规定，本节不逐项记录单纯的语言润色，重点说明模型、程序、数据处理和数值结论相关内容。

| AI 辅助内容 | 处理结果 | 人工修改或核验方式 |
|---|---|---|
| 异常循环识别和插值建议 | 修改后采纳 | 核对同策略重复电池、相邻循环和公开实验协议；仅修复3处字段，保留原始值和审计标记 |
| Q1三类候选曲线模型及比较程序 | 比较后部分采纳 | 统一采用整块电池留一验证；主模型按验证误差和排序稳定性选择，其他模型作为敏感性对照 |
| 将外推 `T80` 用作寿命指标 | 限制性采纳 | 数据中无真实80% SOH终点，因此只作情景外推，不用于主模型选择或真实精度验证 |
| Q2单阈值 `ridge_Jhigh70` 解释模型 | 未采纳为最终模型 | 正式 bootstrap、选择校正置换和极端策略删除检验未通过预设硬门 |
| Q2完整三参数或更复杂层次模型 | 未采纳 | 有效策略坐标过少且高度混杂，增加复杂度不能解决参数不可辨识问题 |
| Q3特征、调参与模型组合实现 | 修改后采纳 | 修正绝对SOH阈值、前缀数据边界和嵌套预处理；增加前缀不变性和边界测试 |
| 在smoke阶段按测试电池误差淘汰Q3模型 | 未采纳 | 该做法会利用保留电池答案造成选择偏差；smoke仅判断工程可行性 |
| Q4连续参数响应面优化 | 未采纳 | oracle坐标压力测试仍失败，不能支持未观测参数组合的连续最优结论 |
| Q4离散Pareto与bootstrap推荐 | 修改后采纳 | 同时报告点估计前沿、选择频率、样本量和敏感性，推荐严格限制在9个已观测策略内 |
| review或子任务审查提出的修改 | 逐项核实后选择性采纳 | 对照程序、CSV、测试和题目要求；错误或证据不足的意见不采纳，并在 `.log/review/` 记录理由 |

人工核验主要包括以下方面：

1. 官方题面和 `data/raw/` 保持只读，清洗数据单独写入 `data/processed/`；
2. 数据行数、电池编号、策略映射、训练测试边界和关键字段由测试脚本断言；
3. 模型选择按整块电池交叉验证，不将同一电池的不同循环随机拆入训练集和验证集；
4. bootstrap、置换检验和全量实验保留固定随机种子、结果清单和阶段报告；
5. 论文数字必须能够追溯至 `result/q1/`—`result/q4/` 的权威 CSV 或工作簿；
6. review意见只有在与数据、程序和结果文件一致时才进入最终结论。

## 5. 人工主导内容与责任声明

以下工作由参赛队主导完成并作出最终决定：

- 将题目分解为数据整理、参数效应分析、早期预测和策略优化四个阶段，并制定各阶段的验收条件；
- 确定原始数据不得修改、清洗数据显式分离以及异常处理必须最小干预的原则；
- 确定整块电池是交叉验证、bootstrap和统计推断的基本单位；
- 选择各问正式评价指标，决定候选模型的保留、降级和淘汰；
- 判断哪些结果属于描述性关联、预测结果或情景外推，限制因果性和外推性表述；
- 对照程序输出、CSV、测试结果和日志核对论文数字，决定最终推荐策略和论文结论。

AI 输出不作为原始数据、实验观测或最终结论直接采用。参赛队对模型选择、程序运行、数值核验、论文表述和全部提交内容承担最终责任。
